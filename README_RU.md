# AiS-Bot

Открытый Telegram-бот-помощник на Python и aiogram. Бот подключается к
совместимому с AiS API сервису, хранит данные аккаунтов и модерации в SQLite,
а историю диалога держит в памяти процесса.

[English version](README.md)

## Возможности

- Выбор модели из каталога в `AI/models.py`, просмотр моделей по провайдеру и
  случайный выбор. При запуске каталог API сверяется с каталогом бота;
  доступность моделей зависит от вашего аккаунта AiS API.
- Текстовый чат и анализ фотографий через AiS API.
- Локальное извлечение текста из TXT, Markdown, кода и других текстовых
  форматов, CSV, TSV, XLSX, DOCX и текстовых PDF до отправки выбранной модели.
- Поиск в интернете через Tavily для запросов о текущих событиях и явных
  поисковых запросов; бот прикладывает полученные ссылки-источники.
- Обязательная входная модерация, автоматические предупреждения и блокировки,
  апелляции пользователей и инструменты администратора. Адаптивная проверка
  Safety в режиме shadow настраивается отдельно и сама по себе не применяет
  санкции.
- Уровни доступа Standard/Trusted, доступ к Premium Models, дневные лимиты и
  индивидуальные переопределения лимитов.
- Хранение аккаунтов, учёта использования, модерации, апелляций и аудита в
  SQLite; автоматические миграции схемы и обслуживание сроков хранения.

Обработка аудио и видео, OCR сканированных PDF, генерация изображений и
прямой inference через AWS/Azure **не реализованы**. Запросы к моделям и
Safety выполняются через настроенный AiS API.

## Архитектура

Путь запроса и границы хранения описаны в
[Docs/architecture.md](Docs/architecture.md). Идентификаторы моделей и их
возможности определены в `AI/models.py`; пользователям показываются только
публичные модели. Внутренний идентификатор провайдера сохранён для совместимости
с настройками, но runtime отправляет запросы в AiS API, а не напрямую
провайдерам облачных моделей.

## Технологии

- Рекомендуется Python 3.12
- aiogram 3.x и asyncio
- OpenAI Python SDK используется как транспорт для AiS API
- SQLite с append-only миграциями
- Tavily Python SDK для веб-поиска
- Автоматические тесты на `unittest`

Точные версии прямых зависимостей закреплены в
[`requirements.txt`](requirements.txt).

## Требования

1. Python 3.12 (Python 3.10+ может работать, CI запускается на 3.12).
2. Токен Telegram-бота, созданного через [@BotFather](https://t.me/BotFather).
3. URL AiS API и API-ключ для совместимого backend. Backend должен публиковать
   точные публичные идентификаторы моделей из `AI/models.py`, совместимые с
   OpenAI endpoints списка моделей и chat completions, а также поддерживать
   контракт AiS Safety, описанный ниже.
4. API-ключ Tavily. Сейчас приложение требует его при запуске, потому что
   клиент веб-поиска создаётся даже если конкретный запрос не вызывает поиск.

Проект не содержит inference-сервера или отдельного сервера баз данных.
Доступ к исходному production аккаунту не требуется, если вы используете
собственный совместимый AiS API и собственные учётные данные.

## Установка

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

### Linux или macOS

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните необходимые значения в `.env`. Не коммитьте этот файл:
`.gitignore` исключает его и локальные runtime-данные.

## Настройка Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather), создайте бота командой
   `/newbot` и скопируйте токен непосредственно в локальную настройку
   `BOT_TOKEN`.
2. Укажите числовые Telegram user ID доверенных операторов в
   `ADMIN_USER_IDS`, разделяя их запятыми. Пустое значение отключает права
   администратора. Для проверки доступа используется ID, а не username.
3. Храните токен в секрете. Если он раскрыт, отзовите его через BotFather и
   замените локальное значение.

Бот использует long polling. Для одного токена и файла базы запускайте только
один активный процесс.

## Интеграция с AiS API

Укажите собственный URL сервиса в `AIS_API_BASE_URL`, а ключ, выданный этим
сервисом, — в `AIS_API_KEY`. Не помещайте учётные данные в URL. В качестве
base URL можно указать origin сервиса или путь `/v1`; клиент приводит его к
формату `/v1`.

При запуске бот вызывает `GET /v1/models` и требует совпадения полученных
идентификаторов с пользовательским каталогом из `AI/models.py`. Для чата
используется `POST /v1/chat/completions`; изображения передаются в этот же
endpoint. Обязательная модерация и shadow assessment используют
`POST /v1/safety/assess`. AiS Safety API должен поддерживать фиксированные
контракты `ais_safety_v1` и `ais_safety_v2`, ожидаемые
`AI/safety_client.py`. Если обязательная проверка Safety недоступна, бот
отказывается продолжать запрос. Не отключайте модерацию как обходной путь.

Каталог моделей задаётся в исходном коде, а не переменной окружения. Чтобы
использовать другой каталог backend, измените `AI/models.py` и соответствующие
тесты согласно документированным ID и возможностям backend, затем проверьте
совместимость API перед запуском. Маршрутизация моделей, credentials провайдеров
и интеграции с upstream-провайдерами относятся к AiS API.

## Переменные конфигурации

Обязательны `BOT_TOKEN`, `AIS_API_KEY`, `AIS_API_BASE_URL` и `TAVILY_API_KEY`.
У остальных переменных есть значения по умолчанию. В `.env.example` указаны
только пустые заглушки для секретов.

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `BOT_TOKEN` | — | Токен Telegram-бота от BotFather. |
| `AIS_API_KEY` | — | Ключ для настроенного AiS API. |
| `AIS_API_BASE_URL` | — | Origin AiS API или base path `/v1`; нужен HTTP(S) URL без credentials, query и fragment. |
| `TAVILY_API_KEY` | — | Ключ Tavily; требуется текущей конфигурации при запуске. |
| `SUPPORT_CONTACT` | пусто | Необязательный публичный контакт, отображаемый в сообщениях поддержки и отказа в доступе. |
| `AI_MAX_CONCURRENT_REQUESTS` | `4` | Положительный лимит параллелизма; router требует минимум `2`. |
| `AI_DEFAULT_MAX_OUTPUT_TOKENS` | `4096` | Верхняя граница вывода, дополнительно ограниченная метаданными модели. |
| `AI_RETRY_COUNT` | `0` | Оставлена для совместимости; бот не повторяет неоднозначные inference-запросы. |
| `AI_REQUEST_TIMEOUT_SECONDS` | `120` | Таймаут запросов к AiS API. |
| `SAFETY_SHADOW_ENABLED` | `true` | Запуск адаптивной Safety-проверки shadow. Её результаты сами по себе не применяют санкции; дополнительные вызовы API могут быть платными. |
| `SAFETY_SHADOW_QUEUE_SIZE` | `32` | Максимальный размер очереди shadow в памяти. |
| `SAFETY_SHADOW_TIMEOUT_SECONDS` | `20` | Настройка таймаута shadow assessment. |
| `SQLITE_PATH` | `data/aiscloudbot.sqlite3` | Путь к SQLite; относительные пути считаются от каталога проекта. |
| `SQLITE_BUSY_TIMEOUT_MS` | `5000` | Таймаут ожидания SQLite в миллисекундах. |
| `ADMIN_USER_IDS` | пусто | Числовые Telegram user ID администраторов через запятую. |
| `USAGE_RETENTION_DAYS` | `90` | Срок хранения подходящих записей об использовании. |
| `MODERATION_RETENTION_DAYS` | `90` | Срок хранения подходящих событий модерации и Safety evaluations. |
| `AUDIT_RETENTION_DAYS` | `365` | Срок хранения подходящих записей аудита администратора. |
| `STANDARD_DAILY_LIMIT` | `50` | Лимит inference Standard по умолчанию на UTC-день. |
| `TRUSTED_DAILY_LIMIT` | `500` | Лимит Trusted по умолчанию; `0` означает безлимит. Индивидуальные значения имеют приоритет. |
| `HIGHER_COST_DAILY_LIMIT` | `15` | Общий дневной лимит для моделей Higher-cost. |
| `GROK_ACCESS_CODE` | пусто | Необязательный код доступа к Premium Models. |
| `PREMIUM_ACTIVATION_CODE` | пусто | Необязательный код активации Trusted-доступа. |
| `ACTIVATION_MAX_ATTEMPTS` | `5` | Число неудачных попыток активации в заданном окне. |
| `ACTIVATION_WINDOW_SECONDS` | `900` | Окно подсчёта попыток активации. |
| `ACTIVATION_COOLDOWN_SECONDS` | `900` | Пауза после превышения числа неудачных попыток. |

Для кодов активации используйте уникальные длинные значения и храните их
только в приватном окружении процесса. Пустое значение отключает
соответствующий способ активации.

## База данных и обработка данных

SQLite автоматически создаётся при запуске. Миграции схемы применяются
автоматически; перед обновлением существующей схемы создаётся проверенная
резервная копия. Храните базу на доступной для записи постоянной **локальной**
файловой системе с поддержкой SQLite WAL. Не используйте один SQLite файл
для нескольких экземпляров бота или неподдерживаемую сетевую файловую систему.

История диалогов и FSM-состояние находятся в памяти процесса и теряются при
перезапуске. Настройки аккаунта, usage-записи, события модерации, апелляции и
аудит администратора хранятся в SQLite согласно срокам retention. Не включайте
production базы данных и резервные копии в исходный код.

## Локальный запуск

```sh
python main.py
```

При запуске бот проверяет каталог AiS API, открывает SQLite, выполняет
обслуживание и начинает Telegram long polling. Остановите его обычным
прерыванием процесса, чтобы клиенты и база были закрыты корректно.

Автоматические проверки:

```sh
python -m compileall -q Admins AI Handlers Reader Search Services Storage Tests Utils app_context.py config.py main.py state.py
python -m unittest discover -s Tests -p "test_*.py" -v
python -m pip check
```

CI также запускает Ruff, `pip-audit` и Gitleaks. Live smoke-скрипты в `Tests/`
запускаются отдельно: они могут выполнять реальные API-вызовы и не входят в
offline unit-test команду.

## Развёртывание

- Используйте поддерживаемый Python runtime, process supervisor и постоянный
  локальный volume для `SQLITE_PATH`; на один токен бота нужен ровно один
  polling-процесс.
- Передавайте секреты через secret/environment manager хоста; не встраивайте
  `.env` в образы и не добавляйте его в Git.
- Ограничьте файловый доступ учётной записью сервиса. Защищайте резервные
  копии и периодически проверяйте восстановление.
- Используйте TLS для удалённого AiS API. До отправки контента пользователей
  ознакомьтесь с правилами обработки данных AiS API и Tavily.
- В репозитории нет production workflow развёртывания, проекта AWS Amplify,
  webhook или конфигурации инфраструктуры.

## Безопасность и приватность

Не коммитьте токены Telegram, ключи AiS API/Tavily или коды активации.
Считайте сообщения, файлы, фотографии и ответы моделей потенциально
чувствительными: они могут отправляться в настроенный AiS API, а подходящие
запросы — также в Tavily. Настройте retention и сообщите пользователям об
обработке их данных. Логи не должны содержать исходные credentials и текст
диалогов, но их файлы всё равно следует защищать и проверять конфигурацию
логирования.

Доступ администратора задаётся числовыми ID в `ADMIN_USER_IDS`, а операции
повторно проверяются сервисным уровнем. Блокировки, ограничения и апелляции
сохраняются; коды доступа не записываются в данные пользователей. Для
inference требуется успешная входная Safety-проверка.

## Устранение неполадок

- **Не задана переменная окружения:** заполните обязательные поля `.env`; не
  отправляйте секреты в issue.
- **Ошибка catalog mismatch:** проверьте, что AiS API публикует все точные
  видимые model ID из `AI/models.py` и что ключ имеет к ним доступ.
- **Ошибка авторизации или Safety:** проверьте ключ, base URL и контракты
  chat/Safety backend. Бот не обходит Safety, если endpoint проверки
  недоступен.
- **Ошибка SQLite WAL или блокировки:** используйте доступный для записи
  постоянный локальный путь и убедитесь, что база не занята вторым процессом.
- **Нет админ-управления:** задайте числовые Telegram user ID в
  `ADMIN_USER_IDS` и перезапустите процесс.
- **Аудио, видео или сканированный PDF:** эти типы сейчас не обрабатываются;
  используйте текст, поддерживаемый документ или фотографию.
- **Поиск недоступен:** проверьте `TAVILY_API_KEY` и сетевой доступ. Обычный
  чат может продолжиться, если поиск не вернул результаты.
